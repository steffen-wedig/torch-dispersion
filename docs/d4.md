# DFT-D4 in torch-dispersion

`torch_dispersion.d4.d4_dispersion` evaluates the full DFT-D4 dispersion energy, forces and stress for
molecules and fully periodic cells. It is the dftd4 4.3.0 `d4` model with EEQ-2019 charges and
rational (Becke–Johnson) damping, for both the two-body term and the ATM term. The oracle is the
pinned PyPI package `dftd4==4.3.0`. It agrees to 1e-17 Hartree in energy, 1e-18 Hartree/bohr in
molecular gradients and 1e-16 Hartree in virials, and periodic gradients pass the 1e-9
Hartree/bohr test tolerance. Do not compare against dftd4 < 4.1.1 (see
[Older dftd4 versions](#older-dftd4-versions-periodic-atm-gradient)).

```python
from torch_dispersion import D4Settings, d4_dispersion, TorchD4Calculator

settings = D4Settings.from_functional("r2scan")  # r2SCAN-D4
result = d4_dispersion(numbers, positions, cell, pbc=True, settings=settings, charge=0.0)
result.energy, result.forces, result.stress, result.charges
atoms.calc = TorchD4Calculator(settings, charge=0.0)
```

The damping parameters are the functional's `d4.bj-eeq-atm` entry in dftd4's
`parameters.toml`; `s6 = 1`, `s9 = 1` and `alp = 16` are the defaults. Entries always set s8, a1
and a2; 31 of the 118 also set s6 and/or s9 (double hybrids, e.g. B2PLYP s6 = 0.64, and some 3c
methods). `D4Settings.from_functional(name, atm=True, **overrides)` reads a frozen copy of that
table (`src/torch_dispersion/d4/functionals.json`, written by
`scripts/export_d4_functionals.py` from dftd4 4.3.0; `D4Settings.functionals()` lists the
names):

- The name is matched case-insensitively and otherwise exactly, as
  `dftd4.parameters.get_damping_param` does (`r2scan-3c`, `wb97x-2008`, `pbe0_2`). An unknown
  name raises `ValueError` with the list of names.
- The merge order is defaults → entry → `atm=False` (s9 = 0, so the ATM term and its neighbour
  list are skipped) → `overrides`. The overrides set any other field, e.g.
  `D4Settings.from_functional("pbe", atm=False, device="cpu", compile=False)`.
- dftd4 is not needed at runtime; the tests check every entry against
  `get_damping_param`.

The cutoffs default to
dftd4's: two-body 60 bohr, ATM 40 bohr, D4 CN 30 bohr. The EEQ CN range of 25 bohr is fixed,
because it is part of the EEQ-2019 model.

## Definition (dftd4 4.3.0, multicharge 0.5.0, mctc-lib 0.6.1)

1. **D4 CN:** CN_i = Σ_j den_ij · ½ (1 + erf(−7.5 (r − Rc) / Rc)).
   - Rc = Rcov_i + Rcov_j, the D3 covalent radii scaled by 4/3.
   - den_ij = k4 exp(−(|EN_i − EN_j| + k5)² / k6), with Pauling electronegativities.
   - Hard cutoff.
2. **EEQ charges:** the bordered system [A 1; 1ᵀ 0] [q; λ] = [x; Q].
   - x_i = −χ_i + κ_i CN'_i / √(CN'_i + 1e-14).
   - CN' is the erf CN without the EN factor, 25 bohr, capped smoothly at 8 by
     log(1 + e⁸) − log(1 + e^(8 − CN)).
   - For molecules: A_ij = erf(r / √(σ_i² + σ_j²)) / r and A_ii = η_i + √(2/π) / σ_i.
   - For cells: multicharge's Ewald form, described next.
3. **Weights and C6:** w_ia = ζ_ia(q_i) · Σ_{g ≤ ngw_a} exp(−6g (CN_i − CN_a)²) / norm.
   - ζ(q) = exp(3 (1 − exp(2 η_i (1 − (q_a + Z_i) / (q + Z_i))))).
   - The norm-underflow fallback is one-hot on the reference with the largest CN.
   - C6_ij = Σ_ab w_ia w_jb C6_ab, where C6_ab is the trapezoid Casimir–Polder integral of the
     reference α(iω).
   - The two-body term uses the EEQ charges. The ATM term uses q = 0, as dftd4 does.
4. **Two-body term:** E2 = −½ Σ_{i,(j,T)} C6_ij (s6 / (r⁶ + R0⁶) + s8 rr / (r⁸ + R0⁸)), with
   rr = 3 r4r2_i r4r2_j and R0 = a1 √rr + a2.
5. **ATM term:** the same triangle sum as D3, with two changes.
   - The damping radius is the product of the three BJ radii R0_ij.
   - The exponent is alp / 3. D3 uses (alp + 2) / 3.
   - It reuses `torch_dispersion.kernel` unchanged.

### Periodic EEQ: replicated, not re-derived

multicharge does not use a converged Ewald sum. It truncates both sums at a fixed range:
- **Images:** every pair uses its Wigner–Seitz minimum images over the ±1 block of 27
  translations. Ties within 0.01 bohr² are averaged.
- **Direct sum:** erf(γr)/r − erf(αr)/r over a fixed 5 × 5 × 5 block of translations.
- **Reciprocal sum:** the 124 shortest G vectors of the 5 × 5 × 5 reciprocal block.
- **Splitting:** α comes from a bisection on the lattice (`get_alpha`) and is held fixed under
  strain.

The result depends on these truncations at roughly the 1e-8 level, so `d4/eeq.py` replicates
them. That includes two details that are easy to miss:

- **Wrapping:** dftd4's API wraps all positions into the central cell
  (`wrap_to_central_cell`, fractional [0, 1) with a 1e-14 tolerance) before building the
  model. The ±1 search finds minimum images only for wrapped positions. torch-dispersion searches on
  positions wrapped by the same rule and folds the wrap offsets into the image shifts, so the
  caller's (possibly unwrapped) positions stay the differentiable input.
- **Self-pair lookup:** for a self pair (i, i) multicharge skips the origin candidate and then
  indexes its translation table one entry too early. This is replicated too. Within the
  truncation it is harmless.

The reciprocal part is exactly periodic, so it factorises into structure factors, an N × 124
matmul. The direct part is evaluated in pair chunks, and its backward pass recomputes each chunk
under autograd, so memory stays bounded.

## Implementation

The structure is the same as the D3 ATM (`torch_dispersion.atm`):

1. **Graph stage:** positions and strain → D4 CN and EEQ CN → charges → C6(q) and C6(0).
   - The CN and C6 functions are compiled with dynamic shapes.
   - EEQ runs eagerly, always in float64. Its gradient is plain autograd through
     `torch.linalg.solve`.
2. **Blocked stage, on detached C6:**
   - The two-body kernel (`d4/two_body.py`) evaluates B centres × `pair_tile_size` neighbours
     per call, with analytic gradients and scatter-add accumulation.
   - The ATM kernel is the D3 one, with an R0 table of BJ radii.
3. **Chain closure:** one `torch.autograd.grad` through both C6 matrices adds the CN and charge
   contributions.

Reference tables are in `d4/reference_data.npz`, written by
`scripts/export_d4_reference_data.py`. The sources are tad-dftd4, tad-multicharge and tad-mctc.
- tad-multicharge stores the EEQ parameters, and tad-dftd4 builds r4r2, in float32. The export
  parses those literal values from the source text in float64.
- The reference α(iω) are evaluated in float64 with the default ga = 3, gc = 2.
- `tests/test_d4_data.py` checks CN, charges, C6 and polarisabilities against dftd4's
  `get_properties`. Against dftd4 4.1.0 every quantity agreed to ≤ 2e-14 relative.
- dftd4 4.3.0 solves the EEQ system less precisely. On the 28-atom all-element cluster its
  charges leave a residual of ~5e-12 in the EEQ equations (cond ≈ 50), against ~3e-15 for
  torch-dispersion. The test therefore compares charges at 1e-11 absolute, and the charge-scaled C6
  and polarisabilities at 1e-10 relative. The CN stays at 1e-12. Energies are unaffected at
  the 1e-10 Hartree tolerance.

## Older dftd4 versions: periodic ATM gradient

dftd4 up to 4.1.0 returned a wrong analytic gradient for the ATM term in periodic systems. In
`src/dftd4/damping/atm.f90`, `get_atm_dispersion_derivs` multiplied each triangle's energy, the
CN and charge derivatives and the virial by the counting factor `triple`, but added the position
gradient terms (`dGij`, `dGik`, `dGjk`) without it. `triple` is 1/2 or 1/6 only for triangles
through periodic images of one atom, so molecules, energies, virials and the two-body term were
unaffected. The periodic gradient was off by about 1e-6 Hartree/bohr on the fixture crystals.
torch-dispersion's gradient agreed with finite differences of dftd4 4.1.0's energy to 5e-14.

The bug was fixed upstream in dftd4/dftd4#359, released in 4.1.1. The energy definition did not
change between 4.1.0 and 4.3.0 at default settings: the reference tables are the same, and
mctc-lib 0.6.1 only adds Hessian helpers. torch-dispersion results are the same against either version,
except for that gradient. The tests pin `dftd4==4.3.0`.

## Oracle coverage

dftd4 4.3.0's Python API sets the real-space cutoffs with `set_realspace_cutoff(disp2, disp3,
cn, width2, width3)`. The CPU tests use shortened cutoffs for periodic cells
(`tests/test_d4_dispersion.py`). The default 40 bohr ATM cutoff on cells and the liquid boxes are
`slow` tests, meant for a GPU. dftd4's smoothing widths (`width2`, `width3`, 4.2.0 and later) are
not implemented in torch-dispersion; the default width of 0 means hard cutoffs, which is what
torch-dispersion uses. The CN and charge internals are only exposed through `get_properties`, at the
default cutoffs (`tests/test_d4_data.py`).
